# M1 — Vehicle Motion Test

## Purpose

This is a component-motion proof using the supplied full RX-7 glTF scene. It is not yet a driving game and does not include physics, acceleration, braking forces, road contact, transmission or world simulation.

## Controls

- Wheel spin test: rotates the four wheel assemblies at a fixed demonstration rate.
- Front-wheel steering: moves the front wheel pivots between -35° and +35°.
- Pop-up headlights: opens/closes the two source headlight assemblies with a short transition.
- Headlights: changes the headlight lens emission and enables the two spotlights when the pop-ups are raised.
- Brake lamps: increases the red rear lamp emission.
- Left/right indicators and hazard: flashes the orange indicator materials.

## Implementation notes

- The source glTF has no animation clips. Motion is generated by a runtime Three.js rig.
- Wheel subassemblies are detected using the source hierarchy. Tyre/rim/disc visual groups are attached to pivots; brake calipers are excluded so they remain stationary.
- Pop-up headlight groups are attached to estimated hinge pivots based on their source bounds.
- Lamp materials are cloned before emissive values are changed, avoiding modifications to shared source materials.
- The runtime rig is included in the single-file offline HTML bundle. The original model, binary buffer, textures and license file remain unchanged.

## Verification checklist

1. Wait until the model status reads ready and the motion control counts appear.
2. Check that the rig reports 4/4 wheels and 2/2 pop-up headlight groups.
3. Start/stop wheel spin and rotate the camera to inspect all four corners.
4. Move the steering slider to both limits and return it to 0°.
5. Open/close the pop-up headlights and check that the assemblies move from the body.
6. Toggle headlights and check that the front lenses and forward beams illuminate.
7. Toggle brake lamps and check that the red rear lamps brighten.
8. Test left, right, hazard and off; verify the amber lamps flash on the corresponding side.
9. Repeat with the network disabled to confirm the standalone file still loads.

## Automated rig test

`npm run test-motion` reconstructs the original glTF node hierarchy and uses the source accessors' bounding boxes to test the actual named part groups without requiring a GPU. It asserts that all four wheel pivots and both pop-up headlight pivots are found, that wheel rotation and front steering change their transforms, that pop-up opening changes its transform and enables a spotlight, and that brake/indicator inputs change the expected lamp emission values. This checks rig logic and source-node matching; it does not replace a visual browser test.

## Known limitations

- The wheel-spin test uses a fixed speed, not vehicle speed.
- Pivot positions, wheel axes, pop-up hinge directions and spotlight alignment are estimated from source geometry and need visual validation.
- The steering pivot animates the wheel visual assembly only; it is not yet connected to a steering rack, suspension or physics simulation.
- Material emission is a visual effect. Actual scene lighting from the front is provided by the added spotlights, which still need visual range/aim tuning.
- A successful build confirms compilation and packaging, not that the rendered motion looks correct on every device.
